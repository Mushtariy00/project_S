# 03 - Design (HOW)

## 기술 결정 8개

| 번호 | 선택 | 대안 | 근거 | 트레이드오프 |
|---|---|---|---|---|
| 1 | 백엔드 FastAPI | Django, Express | 타입 검증과 문서가 기본 | 생태계가 Django 보다 얕다 |
| 2 | 프론트 Vanilla JS + Tailwind CDN | React, Vue | 빌드가 없어 즉시 확인 | 규모가 커지면 손이 많이 간다 |
| 3 | DB SQLite + SQLAlchemy ORM | PostgreSQL 즉시 도입 | 설치가 필요 없다 | 동시 쓰기에 약하다 |
| 4 | CSS Tailwind 만 | styled-components | 클래스만 읽으면 된다 | HTML 이 길어진다 |
| 5 | 실시간 폴링 3초 | WebSocket | 구현이 단순하다 | 지연이 최대 3초 생긴다 |
| 6 | 상태관리 모듈 변수 + DOM 직접 갱신 | Redux, Zustand | 흐름이 그대로 보인다 | 화면이 늘면 중복이 는다 |
| 7 | 디자인 시스템 Mac OS 톤 | Material, Ant | 팀이 익숙하다 | 기성 컴포넌트가 없다 |
| 8 | 테마 라이트/다크 토글 | 라이트 고정 | 야간 사용을 돕는다 | 색을 두 벌 관리한다 |

2번을 덧붙인다. 프론트는 백엔드가 같은 오리진에서 제공한다.
`file://` 로 직접 열지 않는다.

3번을 덧붙인다. 나중에 PostgreSQL 로 옮기는 길을 열어 둔다.

## 배포 결정 (심화편 준비)

기초편은 같은 오리진으로 끝난다. 배포는 프론트와 백엔드를 갈라 놓으므로
2번 결정의 전제가 깨진다. 아래는 그 대비다.

| 항목 | 선택 | 근거 | 트레이드오프 |
|---|---|---|---|
| 프론트 호스팅 | Vercel | 정적 파일에 빌드가 필요 없다 | 백엔드를 못 올린다 |
| 백엔드 호스팅 | Railway | 파이썬 프로세스를 그대로 돌린다 | 파일 시스템이 휘발한다 |
| API 주소 | `meta[name=api-base]` | 빈 값이면 같은 오리진을 쓴다 | 배포마다 값을 넣어야 한다 |
| CORS | `CORS_ORIGINS` 환경변수 | 비어 있으면 미들웨어를 안 붙인다 | 주소를 하나 더 관리한다 |

기본값은 전부 기존 동작을 유지한다. 로컬에서는 같은 오리진 그대로 돈다.

Railway 는 파일 시스템이 휘발한다. SQLite 파일은 재배포 때 사라진다.
3번 결정의 PostgreSQL 전환은 배포 시점에 필요해진다.
